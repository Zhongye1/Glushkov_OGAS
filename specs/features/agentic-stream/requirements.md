# Agentic 流式渲染 — 需求

## 背景与目标

Agent 的推理、检索、工具调用和逐 token 的回答都是运行时动态生成的，无法预先渲染。这个功能负责把这一整条实时流以清晰、可追踪的方式呈现给用户，覆盖 Web、Electron、扩展三端。它与分享页的静态回放是互补的两极：一个是运行时生成，一个是定稿回放。

## 用户故事

作为一个正在提问的用户，我希望看到回答逐字流式出现，而不是长时间空白后一次性弹出。

作为一个关心答案依据的用户，我希望看到 Agent 正在检索哪些资料、调用了哪些工具、走了哪几步，以及回答里的引用能对应到具体来源。

作为跨端使用的用户，我希望在桌面端和浏览器里得到一致的流式体验。

## 验收标准

LLM 回答以流式逐步渲染，通过 SSE 或 RSC streaming 传输，不等生成结束就开始呈现。

Agent 的中间步骤（思维链、检索到读取到再检索的工具调用轨迹、状态卡片）实时演进展示，作为客户端状态机驱动。

回答生成过程中动态插入的引用可交互，能展开到对应来源。

流式渲染的组件与逻辑在三端复用，环境相关能力（如中断、复制、打开来源链接）通过 platform adapter 注入，不直接摸宿主全局。

网络中断或流异常时能恢复或给出明确状态，不留下半截无反馈的界面。

## 非目标

不覆盖已定稿对话的静态回放，那属于 share-page 与历史列表。不在服务端 SSR 生成中的内容——流式内容本质是运行时产物，服务端至多直出外壳骨架。
