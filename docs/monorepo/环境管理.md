# 开发环境管理（Nix + Dev Container）

> 本仓库面向跨平台团队（Linux / macOS / Windows）。主方案是 **Nix devShell**（Linux/macOS 原生、Windows 走 WSL2），备选是 **Dev Container**（Windows 或不熟悉 Nix 的成员）。目标：所有成员拿到与 CI 一致的 Node/pnpm/Go/Python 版本与工具链，消除"我机器上能跑"问题。

## 1. 方案选择

| 场景                    | 方案                          | 说明                                                         |
| ----------------------- | ----------------------------- | ------------------------------------------------------------ |
| Linux / macOS           | Nix devShell（推荐）          | `nix develop` 或 direnv 自动加载，版本由 flake.lock 锁定     |
| Windows（主力）         | WSL2 + Nix devShell           | 在 WSL2 里开发，VS Code Remote-WSL；GUI（Electron）走 WSLg   |
| Windows（不想碰 WSL/Nix）| Dev Container                 | `.devcontainer/devcontainer.json`，VS Code + Docker Desktop 一键进入 |
| 服务依赖                | Docker Compose（既有）        | postgres / milvus 等容器化，Nix 不接管服务容器               |
| CI                      | 既有 GitHub Actions（不变）   | 可选：后续用 flake 统一 CI 环境，本地与 CI 完全一致          |

## 2. 安装 Nix

- Linux / macOS / WSL2：官方推荐 **Determinate Nix Installer**（一条命令，支持 WSL，自动启用 flakes）：
  ```bash
  curl --proto '=https' --tlsv1.2 -sSf -L https://install.determinate.systems/nix | sh -s -- install
  ```
- Windows 原生不支持 Nix：请先在 WSL2 里安装 Ubuntu，再执行上面命令。
- 可选安装 direnv + nix-direnv：进入仓库目录自动加载环境，无需手动 `nix develop`。

## 3. 日常用法

```bash
# 方式 A：手动进入
nix develop

# 方式 B：direnv（推荐，进入目录自动加载）
direnv allow
```

进入后自动完成：

- Node.js 22（nixpkgs `nodejs_22`）
- pnpm 由 corepack 锁定为 `11.14.0`（与根 `package.json#packageManager` 一致）
- Go（`go.work` 要求 1.25+）、Python 3.12（arkhiv 要求 >= 3.11）
- git / jq / ripgrep / gnumake / sqlite / docker-compose

首次使用：

```bash
pnpm install && pnpm build   # 工具链（turbo/oxlint/oxfmt 等）经 pnpm 安装，不走 Nix
docker compose -f infra/compose/docker-compose.yml up -d   # 服务依赖
```

## 4. 版本对齐关系

| 工具/语言 | 锁定位置                          | Nix/Dev Container 侧          |
| --------- | --------------------------------- | ----------------------------- |
| Node.js   | 根 `package.json#engines`         | `nodejs_22` / features node:22 |
| pnpm      | 根 `package.json#packageManager`  | corepack `prepare pnpm@11.14.0` |
| Go        | `go.work` / `services/dispatcher/go.mod` | `go`（nixpkgs 最新，>=1.25） |
| Python    | `services/arkhiv/pyproject.toml`  | `python312`                  |
| TS 工具链 | pnpm 依赖（oxlint/oxfmt/turbo 等）| 不装 Nix 侧，避免双份版本     |

## 5. Windows 指南

**路径 A：WSL2 + Nix（推荐）**
1. 安装 WSL2：`wsl --install -d Ubuntu`
2. 在 WSL 内安装 Determinate Nix Installer
3. 用 VS Code Remote-WSL 打开仓库，`nix develop` 进入
4. 注意：Electron 桌面端在 WSL2 里以 WSLg 显示；若遇图形问题，在 Windows 侧跑 `apps/desktop`，代码仍共享

**路径 B：Dev Container**
1. 安装 Docker Desktop + VS Code Dev Containers 扩展
2. 打开仓库 → "Reopen in Container"（自动执行 corepack + `pnpm install`）
3. 适合不熟悉 Nix 或不需要 WSL 的成员

## 5.5 镜像源（国内加速）

- **仓库级已配置**：`flake.nix#nixConfig` 声明 `substituters`——清华 tuna 镜像优先、官方 `cache.nixos.org` 兜底，团队所有人 clone 后即生效。
- **首次提示**：`nix develop` 首次会询问是否接受 flake 配置（输入 `y`，或用 `nix develop --accept-flake-config`；direnv 的 `use flake` 自动接受）。
- **个人全局**：也可在 `~/.config/nix/nix.conf` 写 `substituters = https://mirrors.tuna.tsinghua.edu.cn/nix-channels/store https://cache.nixos.org/`，对非 flake 操作同样生效。
- **多用户 Nix（daemon 模式）必须 root 配置**：客户端/用户级配置的 substituter 会被忽略（`warning: ignoring untrusted substituter ... you are not a trusted user`）。需 `sudo` 编辑 `/etc/nix/nix.conf` 添加：
  ```
  substituters = https://mirrors.tuna.tsinghua.edu.cn/nix-channels/store https://cache.nixos.org/
  trusted-public-keys = cache.nixos.org-1:6NCHdD59X431o0gWypbMrAURkbJ16ZPMQFGspcDShjY=
  ```
  改完 `sudo systemctl restart nix-daemon`。
- 注意：粘贴多行命令时别把 heredoc 标记（`EOF`）写进 nix.conf，会导致配置解析报错。

## 6. 已知注意点

- **`nix develop` 报 `experimental Nix feature 'nix-command' is disabled`**：Archlinux（pacman 安装的 Nix）等发行版默认未启用实验特性，先配置 `~/.config/nix/nix.conf` 写入 `experimental-features = nix-command flakes`（或临时用 `nix --extra-experimental-features 'nix-command flakes' develop`）；首次 `nix develop` 会下载 nixpkgs，需要网络。
- **sharp**：二进制经 npm optionalDependencies 提供，Nix 侧无需额外处理（`allowBuilds.sharp` 已关闭构建脚本）。
- **Electron**：二进制下载与图形环境依赖宿主机，Nix 侧不接管；devShell 已跳过下载，运行 `apps/desktop` 前按 `docs/monorepo搭建记录.md` 第 6 节补装。
- **Playwright 浏览器**：Nix 下建议 `pnpm exec playwright install --with-deps`（会调用系统包管理器安装依赖）；或接受 CI 容器内运行 E2E。
- **首次构建慢**：nixpkgs 求值/下载需要时间；可配置 Cachix 或复用 GitHub Actions 缓存加速。
- **nixpkgs 版本漂移**：`flake.lock` 已锁定；升级用 `nix flake update`，升级后全体成员同步。
- **不要用 Nix 装 TS 工具链**：oxlint/oxfmt/turbo 等由 pnpm 管理（已在 lockfile 中锁定），避免双份版本漂移。

## 7. 备选工具（不采用）

- **Volta / asdf / mise**：只解决 Node/运行时版本，覆盖不了 Go/Python 与系统依赖，且 mises 与 Nix 职责重叠。
- **Docker 作为唯一环境**：开发体验差（文件同步、热重载慢），保留为服务依赖方案。
- **NixOS 强制全员**：团队有 Windows 成员，不可行；用 devShell 而非 OS 级方案。
